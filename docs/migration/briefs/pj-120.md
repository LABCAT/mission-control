TASK PJ-120: Per-tenant setting: when pack credits become usable (on payment / on invoice)

Add a per-tenant setting for when credits from a pack plan become usable: 'on_payment' (default, legacy vwok behaviour) or 'on_invoice'. Generic and documented (packages/payload-jobs/docs), resolved per tenant like other settings; no hard-coded tenant values.
- on_payment: the pack's credits are granted (ledger 'bought' rows) only when the order becomes paid. The credit used for the job bought with the pack follows the job's own payment rule (publish-before-payment stays job-only, as legacy). If the order is cancelled/failed before payment, no credits are granted.
- on_invoice: current behaviour (granted when invoiced).
- Idempotent (one grant per order, existing PJ-24 keys), works with the PJ-31 outbox/deferred events and the Xero payment sync (PJ-118) marking orders paid.
- Tests: both modes, pay later, cancel before pay, re-run/idempotency, tenant isolation. Migration-last if the schema changes (label needs-migration). Money code: review:deep.

DONE WHEN
- Setting exists per tenant (and settings global for single-tenant), default on_payment.
- With on_payment, pack credits appear only after the order is paid; with on_invoice, after invoicing.
- Publish-before-payment affects only the job being posted.
- Tests cover both modes, cancellation, idempotency and isolation; catalogue story added.

CONTEXT / DECISIONS
