GOAL
Global cache invalidation and cache-key rules for the Astro sites: per-tenant content version in KV, CMS hooks bump it.

BINDING DECISIONS (from STATUS.md, quoted briefly)
- Per-tenant content version in Cloudflare KV, included in the edge cache key; CMS hooks bump it on any change to jobs, organisations, pages, menus, taxonomies, plans, site settings; the hourly expiry job (PJ-52) bumps it when jobs expire/featured ends. TTLs: HTML at the edge 7 days; browser max-age 60s; hashed assets 1 year immutable; images/R2 media 1 year. All public pages incl. directories cached. --- Earlier notes (history; the PROMPT and this block win where they differ) ---
[18 Nov, from PJ-35] launchpad's cached()/purgeTags use the Workers Cache API, which is per data centre, so purgeTags only clears the colo that runs it. PJ-41 needs a global purge: the Cloudflare zone purge-by-tag/URL API, or a shared version store (KV) the tags read from.

[19 Nov, founder] DECIDED cache strategy: per-tenant content version in Cloudflare KV, included in the edge cache key; CMS hooks bump it on any change to jobs, organisations, pages, menus, taxonomies, plans, site settings; the hourly expiry job bumps it when jobs expire/featured ends. TTLs: HTML at the edge 7 days; browser max-age 60s (browsers can't be purged); hashed assets 1 year immutable; images/R2 media 1 year. All public pages incl. directories (/jobs, category/location/type pages, organisations) cached this way. Nothing personal in cached HTML (signed-in UI and saved/viewed state client-side). Relative dates ('3 days ago') rendered client-side or as absolute dates. /health is never cached (checks Worker, CMS, DB); UptimeRobot monitors /health per site + CMS.

[19 Nov, founder] Signed-in state on cached pages: sign-in sets the HttpOnly session cookie plus a non-HttpOnly hint cookie (signed_in=1, no PII, same expiry as the session). Inline script swaps 'Sign in' for 'My account' from the hint (no request, no layout shift). Personal bits load from uncached /api/me; a 401 there clears the hint and reverts the header. /account and forms never cached; /account with an invalid session redirects to sign-in with a return URL. Sign-out clears both.

[19 Nov, founder] Junk URLs must never reach the CMS/DB: normalise the cache key before lookup. Unknown query params are dropped; known params (type, salary, posted, q, etc.) keep only values that exist (validated against the tenant's taxonomy/filter lists, themselves cached per content version); params are sorted. If normalisation changed the URL, 301 to the canonical URL (so /jobs?type=asdf123 -> /jobs, served from cache). Free-text keyword search is the only open input: rate-limited and cached per normalised query.

[19 Nov] Tracking params exception: utm_*, gclid, gbraid, wbraid, fbclid, msclkid, ttclid, li_fat_id, ref (list configurable) are IGNORED for the cache key but KEPT in the URL (never 301-stripped), so client-side analytics/Zaraz see them (e.g. ChatGPT adds utm_source=chatgpt.com). Document in the README.
