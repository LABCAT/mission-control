## Decisions already made (don't relitigate)

- **Stack:** Payload 4 beta + TanStack. Neon via Hyperdrive. Astro on Workers for the sites, aiming for a PageSpeed score of 100. One multi-tenant CMS Worker.
- **Packages:**
  - `packages/payload-jobs`
  - `packages/payload-xero` (late)
  - `packages/payload-wp-import`
  - `packages/launchpad`: the Astro theme on Rocketship (renamed from "site-kit")
- **Rocketship first:** a generic UI component goes into Rocketship, and only job-board compositions go in launchpad.
- **Employers use the Payload admin** for v1. **Job seekers have no accounts:** apply is a form, and alerts are email-only with a double opt-in.
- **Dropped** (per `USAGE.md`): online gateways (100% of orders are bank-transfer invoices), featured add-ons, resumes and resume access, blog, the separate volunteer flow, MailChimp.
- **Do Good Jobs NZ is out of scope.** The legacy Xero code mentions it.
- **Repo shape:**
  - Not a GitHub fork, because the same account can't fork its own repo.
  - The `upstream` remote is orbit, and pushing to it is disabled.
  - Our CI is a separate workflow, so orbit's `ci.yml` isn't touched.
- **Migrations:** agents create them as a separate commit with the `migration` label. Shane merges, and orbit's release workflow (tag) applies them to Neon.
